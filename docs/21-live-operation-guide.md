# 21 · 真实运营指南（Live Operation Guide）

> 给非开发同事看的「每周怎么用图文工厂」。不需要任何编程知识。
> 前置：管理员已完成部署 + 配置密码（见 docs/22 §6）。你只需要一个浏览器。

## 你的每周节奏（约 60-90 分钟/周）

```
周一上午          周二~周四         周五
┌──────────┐   ┌──────────┐   ┌──────────┐
│ 生成计划  │ → │ 审核+发布 │ → │ 回流数据  │
│ 确认生产  │   │ 内容      │   │ 复盘调整  │
└──────────┘   └──────────┘   └──────────┘
```

## 第 1 步 · 打开工作台，看「今天需要处理什么」

登录后进入**运营工作台**。最上面的橙色卡片就是你的待办清单——
系统自动从 7 个来源聚合（周计划/工作流/审核/发布/连接器/数据质量），做完动作条目自动消失。

> 💡 如果显示「数据不足：还没有真实回流数据，当前建议主要依据趋势与内容价值」，
> 这是正常的冷启动提示——前 2-3 周没有历史数据时，系统会明确告诉你推荐主要靠趋势判断。

## 第 2 步 · 生成并确认本周计划（约 10 分钟）

1. 点击**「生成本周内容计划」**——系统扫描趋势/上周表现/知识缺口，给出带评分依据的选题。
2. 进入**本周内容计划**，逐条看每项的评分明细（基础分 + 趋势 + 表现 + 转化 + 缺口 = 最终分）。
3. 不想要的点**拒绝**；都 OK 就点**「确认本周选题」**→ **「确认并开始生产」**。

## 第 3 步 · 审核 AI 产出（约 20 分钟）

AI 工作流跑完后，进入**待审核 → 内容审核**：

- **直接通过**：内容可用，点通过（会计入「直接通过」验收统计）。
- **需要修改**：打开内容详情 → 「人工编辑」保存新版本 → 回审核点通过（计入「修改后通过」）。
- **不可用**：点打回。

生产监控台（/production）能看到本周 AI 成本和内容验收率——每周看一眼，心里有数。

## 第 4 步 · 发布包（GitHub 周榜为例，约 15 分钟）

1. 进入**发布包** → 点**「生成本周发布包」**。系统从 GitHub 快照自动组装：
   总榜文案 + 5 条项目文案 + 极简提纲 + 平台标题 + 标签 + 图片顺序说明。
2. 进入**品牌资产**，上传封面和 5 张项目卡片（PNG/JPG）。
3. 回到发布包详情，把封面/卡片**按顺序挂载**（顺序就是发布时的图片顺序）。
4. 三项 QA 逐个确认：**事实 QA**（数字和快照一致）/ **品牌 QA**（Logo 规范）/ **内容 QA**（标题/CTA/违禁词）。
5. 三项全过 → 点**「标记可发布」**。复制正文到公众号/平台发布。
6. 发布完成后点**「确认已发布」**。

> ⚠️ 正式 Logo 上传后请点**「锁定」**——锁定后任何自动化都不能替换它。

## 第 5 步 · 数据回流（约 15 分钟）

发布 2-3 天后，从小豆芽导出 CSV，进入**小豆芽**页面：

1. **作品 CSV** 上传（第一次导历史数据勾选「历史导入」；系统自动检测编码，GBK/UTF-8 都可以）。
2. 系统自动匹配到你的发布计划（作品 ID → 链接 → 平台+时间 → 标题相似），不确定的进**未匹配作品**手动选。
3. 有失败行？点**「重试失败行」**，或**「导出失败行」**修正后重新上传。
4. 同一文件重复上传会被自动跳过，放心操作。
5. **账号 CSV** 同理（粉丝数快照，用于涨粉归因）。

### 每日小豆芽数据回流（/screen 抄数，推荐日常方式）

不用导出文件——每天小豆芽数据更新后（12 点），在项目目录的 Claude Code 里逐平台抄数：

```
小豆芽切到抖音数据页   → /screen 抄数
小豆芽切到小红书数据页 → /screen 抄数
小豆芽切到B站数据页    → /screen 抄数
小豆芽切到视频号数据页 → /screen 抄数
小豆芽切到公众号数据页 → /screen 抄数
↓
Content OS「数据导入」页 → 导入 /screen 抄数数据（① 预览 → ② 确认导入）
   或命令行：pnpm data:import-screen
```

- 每次抄数约半分钟；同一数据日期重复导入会自动更新，不会产生重复数据
- Dashboard「今天需要处理什么」会提醒你哪些平台当天还没抄
- 抄完系统自动完成：账号快照 + 作品快照 + 涨粉基线 + Topic 表现重算，不用手动点计算

## 第 6 步 · 复盘（约 10 分钟）

- **数据分析 → Topic 分析**：看每个 Topic 的五维表现分和推荐动作（加大投入/暂停/饱和…）。
- **涨粉归因**：哪条内容真的带来了粉丝。
- 下周一生成计划时，上周表现会自动参与推荐（Dashboard 优先级队列能看到每条的理由）。

## 出问题时怎么办（自助修复表）

| 情况 | 你要做的 |
|---|---|
| 工作流失败/「需人工介入」 | 生产监控台 → 该行点「重试」（同批次幂等，不会产生重复内容） |
| CSV 部分行导入失败 | 小豆芽页面 → 该批次「重试失败行」或「导出失败行」 |
| 作品匹配错了 | 暂不支持界面解除匹配，标记后由管理员处理（数据层支持重新匹配） |
| 文件传错/重复上传 | 重复文件自动跳过；传错直接传对的文件覆盖 |
| 通知看不过来 | 通知中心可全部标记已读；真正要做的都在 Dashboard 待办里 |

## 每周检查清单（打印友好）

- [ ] 周一：检查 /screen 数据 → 导入 → 生成本周计划 → 确认 → 开始生产
- [ ] 周一：上传上周小豆芽 CSV（作品 + 账号）或用 /screen 抄数代替
- [ ] 处理 Dashboard 待办里的所有 P1（含「AI 需人工介入」时先按 docs/24 §6 修复）
- [ ] 审核全部 AI 内容（直接通过/修改后通过/打回）
- [ ] GitHub 周榜包：QA 三项 → 视觉资产 → 可发布 → 人工发布 → 确认已发布
- [ ] 周五：看一眼 Topic 分析和归因，标记下周想加投的方向
- [ ] **每天（12 点后）：/screen 抄数逐平台 → /data-import 导入 → 处理今日待办**
